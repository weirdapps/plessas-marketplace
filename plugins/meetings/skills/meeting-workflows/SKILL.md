# Meeting workflows

Route by what the user is trying to achieve, not by the words they used.

| The user wants to | Run |
|---|---|
| to be ready for something coming up | `/meetings:meeting-prep` |
| to capture what came out of something that happened | `/meetings:meeting-debrief` |

Tense decides: before the meeting is prep, after it is debrief. If the user
refers to a meeting without making the tense clear, ask which they mean rather
than inferring from the calendar.

Judge by meaning, not by matching words. Requests this skill serves, in English
or Greek: "who am I seeing tomorrow", "what do I need before this call", "go and
find what I actually promised them", "what did we actually agree", "who owns
what now", "put that somewhere I can find it", "log where this landed,
structured", "deal with the session on X", «τι έχω αύριο», «τι πρέπει να ξέρω
πριν τη σύσκεψη», «βρες τι του είχα υποσχεθεί», «τι αποφασίσαμε τελικά», «κράτα
τα action items», «κράτα το κάπου δομημένα», «τακτοποίησε τη σύσκεψη με τον Χ».
These are samples, not an exhaustive list. It also applies when the user simply
recounts how a meeting ended and wants it written down, without asking a
question.

Three shapes that are easy to mistake for other work, and are this skill:

- A request that dictates outcomes and asks only for them to be saved is a
  debrief, not a plain file write, because the house structure is the point.
- A request to retrieve what was said to someone before you next see them is
  prep, not a generic search.
- A request that names a meeting without saying which side of it the user is
  on is this skill above all, because asking which is its job and nothing else
  knows to ask.

## When nothing fits

If the request is clearly about a meeting but neither row serves it, say what
this plugin can do and ask. Do not pick the nearer row.

Writing and sending the follow-up mail is mail work: hand it to outlook-mail
once the debrief has captured the content.
